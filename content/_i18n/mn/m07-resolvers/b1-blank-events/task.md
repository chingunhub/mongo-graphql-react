Чи жижиг events сайтын API-г өвлөж авлаа. Үүнийг бичсэн хүмүүсээс одоо хэн ч байхгүй. Даваа гаригийн өглөө ийм ticket ирлээ:

> **TICKET-5871 — "Events page is blank"** (priority: urgent)
>
> 1. Ops баасан гарагт хаагдсан venue-г устгасан. Тэр цагаас хойш **events хуудас бүхэлдээ хоосон** байна. Нэг ч event алга, зүгээр л хоосон. Response-д `"data": null` гэж байна.
> 2. Зохион байгуулагчид event-ийн нэрийг солиход баталгаажуулалт дээр **хуучин нэр** хэвээр харагдана. Refresh хийвэл шинэ нэр гарч ирнэ.
> 3. Хуудас дээрх огноо `1774224000000` шиг харагдаж байна.
> 4. `/events/oops` нээхэд манай ердийн "event not found" дэлгэцийн оронд "Something went wrong" гарч байна.

Эхлээд playground-ыг ажиллуул. Дөрвийг бүгдийг нь давтаж гаргана. Эхнийхийг нь удаан ширтэх нь зүйтэй: нэг event-ийн нэг venue алга болоод бусад бүх event ч арилсан. Энэ нь зөвхөн энэ codebase-д тохиолдсон давхцал биш. GraphQL хэрхэн execute хийгддэгийн дүрэм, чи үүнтэй өмнө нь тааралдсан.

## Даалгавар

`graphql/schema.ts`, `graphql/resolvers.ts` дотор дөрвөн шинж тэмдгийг хамгийн жижиг зөв өөрчлөлтөөр зас:

1. Venue нь алга болсон ч event бүр жагсаалтад үлдэнэ. Тэр event `venue: null` гэж буцаж, алдаа гарахгүй. Орлуулах venue бүү зохио, event-ийг ч бүү хас.
2. `renameEvent` event-ийг шинэ title-тай нь буцаана.
3. `startsAt` нь ISO string, жишээ нь `2026-03-23T09:00:00.000Z`.
4. Буруу хэлбэртэй id-тай `event(id: ...)` нь байхгүй id-тай адил `null` буцаана. Алдаа гарахгүй.

Model-уудыг бүү хөндө.

## Hints

### Шинж тэмдэг 1-ийг хаанаас хайх вэ

Playground-ийн гаралт дахь алдааг уншаад, түүний гомдоллож буй `!`-г ол. Non-null field `null`-аар resolve болбол GraphQL юу хийдэг вэ, мөн энэ хэр дээш гардаг вэ?

### Шинж тэмдэг 2, 3

Хоёулаа Mongoose чиний resolver-ийн таамагласнаас жаахан өөр зүйл өгч байгаагаас болсон. 2-т: `findByIdAndUpdate` default-оор document-ийн аль хувилбарыг буцаадаг вэ? 3-т: `Date` `String` scalar-д хүрвэл `graphql` үүнийг string болгочихдог, гэхдээ чиний хүссэн хэлбэртэй биш. Field тус бүрийг `Event` дээрх resolver-ээр удирдаж болно.

### Шинж тэмдэг 4

`findById('oops')` `null` буцаадаггүй. Id-г cast хийх үедээ throw хийнэ. Query ажиллуулахаас өмнө тэр string ObjectId байж болох эсэхийг Mongoose хэлж өгч чадна.

### Дөрвийг бүгдийг нь

Schema дахь `venue: Venue`, update дээрх `{ returnDocument: 'after' }`, `.toISOString()` дууддаг `Event.startsAt` resolver, мөн `Query.event` дотор хамгаалалт болгон `mongoose.isValidObjectId(id)`.
