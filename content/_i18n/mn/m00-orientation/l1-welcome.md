Сайн уу. Нэг ч schema бичихээсээ өмнө бүх зүйлийн хэлбэрийг толгойдоо суулгачихъя, учир нь энэ курсийн бүх зүйл нэг зургаас салаалдаг.

React app issue-уудын жагсаалт үзүүлэхэд гайхмаар олон зүйл болдог. Component өгөгдөл асууна, client library cache шалгана, request HTTP-ээр явна, server түүнийг parse хийж validate хийнэ, жижиг function-уудын мод ажиллана, ODM тэдгээр дуудлагыг database command болгон хөрвүүлнэ, дараа нь үр дүн нь бүх замаараа буцаж дээшилнэ. Junior dev-үүд эдгээр давхаргын *нэгийг* л сайн мэдэх нь элбэг. Intermediate dev давхарга бүр хаана эхэлж, хаана дуусахыг мэддэг, тиймээс юм эвдрэхэд аль файлыг нээхээ тэр мэднэ.

Курсийн хэсэг бүр энэ зургийн нэг зурвасыг ойроос үзүүлнэ:

| Part | Давхарга | Чи юу хийж чаддаг болох вэ… |
| --- | --- | --- |
| **I — Mongoose** | Models ↔ MongoDB | schema design хийх, өгөгдлөө validate хийх, query болон update-ийг үр ашигтай бичих, холбоог model хийх, hook болон aggregation бичих |
| **II — GraphQL & Apollo Server** | HTTP ↔ Resolvers | GraphQL schema design хийх, Mongoose-тай харилцдаг resolver бичих, auth болон алдааг зохицуулах, N+1 query-г арилгах, pagination хийх |
| **III — Apollo Client & React** | Component ↔ HTTP | React-аас query, mutate хийх, normalized cache-ийг ойлгох, mutation-ий дараа түүнийг шинэчлэх, pagination хийх, fragment-үүдийг colocate хийх |

## Taskforge

Taskforge бол жижиг issue tracker, жижигхэн Linear эсвэл Jira гэж бод. Дотор нь user-ууд, `TF` шиг key-тэй project-ууд, status, priority, label, assignee-тэй `TF-12` шиг issue-ууд, мөн comment-ууд байна. Төгсөхөд чамд дараах зүйл бий болсон байна:

- validation, index, hook, virtual populate, aggregation-тай **Mongoose** data layer,
- модульчилсан schema файл, token-оор хийсэн auth, зөв error code, DataLoader batching, cursor pagination, search union-тай **GraphQL API**,
- Apollo Client ашигласан, cache update, optimistic UI, fragment, "load more"-той **React** front end.

Дараа нь үүнийг ажиллуулаад (чиний server, чиний UI) дотор нь чөлөөтэй хэсч үзнэ. Одоогоор аль хэсгийг бүтээснийг дээд талын **⚒ Taskforge** товчоос хар.

Энэ app дотор яг одоо ажиллаж буй *жишиг* Taskforge бас бий (дээд талд **API** гэсэн ногоон цэг). Хичээлүүд үүнийг live жишээнд ашигладаг. Засаад ажиллуулж болно, яг энэ шиг:

```graphql-try
query {
  projects {
    key
    name
    issueCount
  }
}
```

Syntax-ийн талаар одоохондоо санаа зовох хэрэггүй. Нэг л зүйлийг анзаар: чи яг гурван field асуусан, яг гурван field буцаж ирсэн.

## Sandbox хэрхэн ажилладаг вэ

Даалгавар workbench дээр нээгдэнэ: зүүн талд тайлбар, баруун талд даалгаврын бүх файлтай editor.

- **Run playground** нь `playground.ts`-ийг ажиллуулж, `console.log`-ийн гаралтыг үзүүлнэ. Чөлөөтэй хэрэглэ, энэ чинь ноорог хуудас. Юу ч үнэлэгдэхгүй.
- **Submit** нь чиний код дээр далд тестүүд ажиллуулж, аль нь давсныг хэлнэ. Давахгүй байгаа тест дээр жижиг чиглүүлэг өгдөг.
- Чи **TypeScript эсвэл энгийн JavaScript** бичиж болно. TypeScript-ийн төрлүүд зүгээр л *хасагддаг*, шалгагддаггүй. Тиймээс төрлийн алдаа чамайг зогсоохгүй ч, аврахгүй.
- MongoDB-д хүрдэг код **жинхэнэ MongoDB** дээр ажиллана, ажиллуулах болгонд шинэхэн, түр database дээр. Чи юуг ч эвдэж чадахгүй, дураараа туршаарай.
- Код чинь автоматаар хадгалагдана. App-аа хэзээ ч хааж болно, бүх зүйл чинь энд хэвээр.
- **Hints** зөөлөн нь эхэлж, бараг хариулт хүртэл нэг нэгээр нээгдэнэ. **Solution** тестээ давсны дараа, эсвэл гурван оролдлого хийсний дараа нээгдэг.

> [!TIP] Гацсан үедээ яах вэ
> Fail болсон *эхний* тестийн message-ийг анхааралтай унш. Чухал нь ихэвчлэн тэр байдаг, бусад нь голдуу түүний үр дагавар. Дараа нь playground дээр `console.log` хий. Хамгийн сүүлд зөвлөгөө үз. Яг энэ дарааллаар.

> [!NOTE]
> **read-only** файлууд бол бэлэн өгсөн helper-ууд. Хамтран ажиллагчийн бичсэн код гэж бод: ашиглаж болно, засахгүй. Гэхдээ дотор нь уншаад үзээрэй, том codebase дээр ч ингэж л сурдаг.

Дараагийнх нь workbench-ийг туршиж үзэх хоёр минутын warm-up.
